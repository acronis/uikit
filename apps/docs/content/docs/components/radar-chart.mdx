## Usage

```tsx
import { RadarChart } from '@acronis-platform/ui-react';
import type { ChartConfig } from '@acronis-platform/ui-react';
```

`RadarChart` is a typed recharts composition over the shared
[`Chart`](/components/chart) primitives — the library's first polar type. Give it
`data`, a per-series `config`, the series to plot (`dataKeys`), and the angular
axis key (`angleKey`) — it renders a themed recharts radar with polar grid, spoke
labels, tooltip, and legend, so you never hand-compose recharts children.

Series are columns of a shared row (as in a bar or line chart), plotted around one
polar angular axis: each `data` row contributes one labelled spoke. Series colors
are supplied by the caller through `config`: each entry maps a data key to a
`label` and a `color`, turned into the `--color-<key>` custom properties the areas
stroke and fill from.

Use it to compare several entities across the same set of quantitative axes — skill
profiles, feature scorecards, test results per subject — with roughly four to eight
axes and a few series. For a single series or a single metric prefer
[`BarChart`](/components/bar-chart): judging value along a radius is hard. Many
series or many axes make the overlapping areas unreadable, and a trend over time
belongs in [`LineChart`](/components/line-chart) or
[`AreaChart`](/components/area-chart).

Pair the chart with a text alternative (caption, summary, or adjacent data table)
and give it an accessible name — `aria-label` / `aria-labelledby` pass through to
the wrapper element. Keep either the legend or the tooltip visible, and keep
`fillOpacity` low enough that overlapping areas stay distinguishable.

> **Design-pending v1**, ported from the demo `RadarChartPlayground`. There is no
> chart token tier yet, so the example colors reference the shared semantic
> `--ui-*` brand/status tokens — a dedicated `--ui-chart-*` data-viz palette is
> pending an upstream design pass. `--ui-background-status-strong-*` is chromatic
> in every brand; `--ui-background-brand-secondary` is brand-dependent, so it is
> not color-stable across brands until the real palette lands.

## Examples

<DemoReact>
  <RadarChartDemo />
</DemoReact>

Two series compared across shared axes, with a themed tooltip and legend:

```tsx
const data = [
  { subject: 'Math', alice: 120, bob: 110 },
  { subject: 'English', alice: 86, bob: 130 },
  { subject: 'Physics', alice: 85, bob: 90 },
  { subject: 'History', alice: 65, bob: 85 },
];

const config = {
  alice: { label: 'Alice', color: 'var(--ui-background-brand-secondary)' },
  bob: { label: 'Bob', color: 'var(--ui-background-status-strong-danger)' },
} satisfies ChartConfig;

<RadarChart
  config={config}
  data={data}
  dataKeys={['alice', 'bob']}
  angleKey="subject"
  className="h-[380px] w-[420px]"
/>;
```

`gridType="polygon"` (the default) draws the web as straight-edged rings.
`gridType="circle"` draws smooth concentric rings instead:

```tsx
<RadarChart config={config} data={data} dataKeys={['alice', 'bob']} angleKey="subject" gridType="circle" />
```

Tune the areas with `fillOpacity` and `strokeWidth`, and mark where each series
crosses each spoke with `showDots`:

```tsx
<RadarChart
  config={config}
  data={data}
  dataKeys={['alice', 'bob']}
  angleKey="subject"
  fillOpacity={0.15}
  strokeWidth={3}
  showDots
/>
```

Toggle the chrome with `showGrid` / `showTooltip` / `showLegend`:

```tsx
<RadarChart
  config={config}
  data={data}
  dataKeys={['alice']}
  angleKey="subject"
  showGrid={false}
  showLegend={false}
/>
```

Replace the tooltip with a configured `ChartTooltipContent` — imported from the
same library, so you still never compose recharts yourself. Its `formatter`
renders each row and `labelFormatter` the header:

```tsx
import { RadarChart, ChartTooltipContent } from '@acronis-platform/ui-react';

<RadarChart
  config={config}
  data={data}
  dataKeys={['alice', 'bob']}
  angleKey="subject"
  tooltipContent={
    <ChartTooltipContent
      formatter={(value, name) => `${name}: ${value.toLocaleString()}`}
    />
  }
/>;
```
