## Usage

```tsx
import { ChartState } from '@acronis-platform/ui-react';
```

`ChartState` is the shared placeholder the [chart](/components/chart) types show **in
place of** the chart itself — while data is in flight, when there is nothing to plot,
or when the fetch failed. It's a compact status block: a leading glyph (spinner,
inbox, or warning) over a centered label. It fills the slot it's given and falls back
to a minimum height in an unsized parent, so it drops straight into the same sized
box a chart would occupy.

Drive it with the required `state` prop (`loading` | `empty` | `error`). Each state
carries a default label, which `message` overrides. The `error` state also takes an
optional `action` — that node is rendered for `error` only, and ignored for `loading`
and `empty`.

Use it whenever a chart can't render yet, and use it across every chart type rather
than hand-rolling a placeholder per chart. For a full-page empty state — illustration,
title, description, primary action — reach for [`Empty`](/components/empty), the
larger page-level sibling. For a bare loading indicator with no surrounding message,
use [`Spinner`](/components/spinner) directly.

The root element **is** the live region: `loading` and `empty` announce politely via
`role="status"`, `error` assertively via `role="alert"`. Those attributes are applied
after the prop spread, so a consumer attribute can't clobber the contract. Two things
to get right on your side: **don't put `aria-busy` on `ChartState`** — put it on the
chart-slot container if you need a busy signal (same guidance as
[`Skeleton`](/components/skeleton)) — and pass a real interactive control, e.g. a
[`Button`](/components/button), as `action` so retry is focusable and keyboard
operable.

> **Design-pending v1**, ported from the Figma InputSelect dropdown states and kept
> visually in step with the shipped `InputSelectStatus`. There is no chart token tier
> yet, so it themes from existing semantic `--ui-*` tokens directly: the label from
> `--ui-text-on-surface-primary`, the empty and error glyphs from
> `--ui-glyph-on-status-info` / `--ui-glyph-on-status-warning`, and the loading
> indicator from the shared [`Spinner`](/components/spinner). The glyph color is never
> the only cue — the label carries the meaning.

## Examples

<DemoReact>
  <ChartStateDemo />
</DemoReact>

The three states, each with its default label — "Data is loading…", "No data found",
and "Something went wrong":

```tsx
<ChartState state="loading" />
<ChartState state="empty" />
<ChartState state="error" />
```

In practice, swap the chart for the matching state inside the same sized slot:

```tsx
function Sales({ status, data, config, refetch }) {
  if (status === 'loading') return <ChartState state="loading" />;
  if (status === 'error')
    return (
      <ChartState
        state="error"
        action={
          <Button variant="ghost" onClick={refetch}>
            Try again
          </Button>
        }
      />
    );
  if (!data.length) return <ChartState state="empty" />;

  return <LineChart config={config} data={data} dataKeys={['sales']} xKey="month" />;
}
```

Override any state's default label with `message`:

```tsx
<ChartState state="empty" message="No results for the selected range" />
<ChartState state="error" message="Could not load usage data" />
```
