## Usage

```tsx
import { FunnelChart } from '@acronis-platform/ui-react';
import type { ChartConfig } from '@acronis-platform/ui-react';
```

`FunnelChart` is a typed composition over the shared [`Chart`](/components/chart)
primitives. Give it `data` (one row per stage), a per-stage `config`, the value
field (`dataKey`), and the label field (`nameKey`) — it renders a themed recharts
funnel (on-chart stage labels and a tooltip included), so you don't hand-compose
recharts children. The legend is opt-in (`showLegend`) — the on-chart labels
already name every stage, so it earns its space only when those labels carry
values or conversions instead.

Stage colors are supplied by the caller through `config`, **keyed by each
`nameKey` value**: `FunnelChart` turns those into the `--color-<name>` custom
properties its segments fill from.

> **Design-pending v1**, ported from the demo `FunnelChartPlayground`. There is no
> chart token tier yet, so the example colors reference the shared brand/status
> tokens — a dedicated `--ui-chart-*` data-viz palette is pending an upstream
> design pass. `--ui-background-status-strong-*` is chromatic in every brand;
> `--ui-background-brand-secondary` is brand-dependent, so it is not color-stable
> across brands until the real palette lands.

## Examples

<DemoReact>
  <FunnelChartDemo />
</DemoReact>

A conversion funnel with on-chart stage labels and a themed tooltip:

```tsx
const data = [
  { stage: 'Visits', value: 5000 },
  { stage: 'Signups', value: 2600 },
  { stage: 'Trials', value: 1400 },
  { stage: 'Purchases', value: 620 },
];

const config = {
  Visits: { label: 'Visits', color: 'var(--ui-background-brand-secondary)' },
  Signups: {
    label: 'Signups',
    color: 'var(--ui-background-status-strong-success)',
  },
  Trials: {
    label: 'Trials',
    color: 'var(--ui-background-status-strong-warning)',
  },
  Purchases: {
    label: 'Purchases',
    color: 'var(--ui-background-status-strong-danger)',
  },
} satisfies ChartConfig;

<FunnelChart
  config={config}
  data={data}
  dataKey="value"
  nameKey="stage"
  className="h-[380px] w-[460px]"
/>;
```

End the funnel flat instead of at a point with `lastShape="rectangle"`:

```tsx
<FunnelChart
  config={config}
  data={data}
  dataKey="value"
  nameKey="stage"
  lastShape="rectangle"
/>
```

Flip the direction with `reversed`, or hide the on-chart labels / tooltip with
`showLabels` / `showTooltip`:

```tsx
<FunnelChart
  config={config}
  data={data}
  dataKey="value"
  nameKey="stage"
  reversed
  showLabels={false}
/>
```

## Labels

`labelFormat` decides what each stage's label says: its `name` (the default), its
`value`, its `percent`, or a pair — `name-value`, `name-percent`, `value-percent`.

A percentage is the stage's share of the **widest stage** — its conversion from
the top of the funnel. Unlike a pie's slices, a funnel's stages are nested subsets
of each other rather than parts of a whole, so a share of the sum wouldn't mean
anything. The base is the largest value, not the first row, so an unsorted funnel
still tops out at `100.0%`.

```tsx
<FunnelChart
  config={config}
  data={data}
  dataKey="value"
  nameKey="stage"
  labelFormat="name-percent"
/>
```

`labelPosition` puts the label beside the segment (`right`, the default, or
`left`) or on it (`inside`). The label color follows: beside the funnel it sits on
the card surface, on a segment it switches to the on-fill token so it keeps its
contrast over a saturated stage color. Override it with `labelFill` only when
neither works on your surface.

<Callout type="warn">
  `inside` only works while every stage is wide enough to hold its text. A
  funnel narrows by definition, so its last stages usually aren't — the text
  runs past the segment onto the surface, where the on-fill color (white in both
  themes) has nothing to sit on and disappears in light mode. Pair `inside` with
  a short format (`percent`, `value`) and let the legend carry the names, or
  keep the labels beside the funnel.
</Callout>

`showValueLabels` adds a second label carrying the value. `valuePosition` places
it, and defaults to the side **opposite `labelPosition`** — so it follows the names
rather than pinning itself to one edge, and the two lists never stack:

```tsx
<FunnelChart
  config={config}
  data={data}
  dataKey="value"
  nameKey="stage"
  showValueLabels
/>
```

`labelFormatter` formats only the numeric part of a label, so a label and its
tooltip can share one formatter. `percentFormatter` formats the conversion share
separately — it receives a fraction (`0.52`) and defaults to `"52.0%"`:

```tsx
import { createTickFormatter } from '@acronis-platform/ui-react';

<FunnelChart
  config={config}
  data={data}
  dataKey="value"
  nameKey="stage"
  labelFormat="name-percent"
  percentFormatter={createTickFormatter(
    { style: 'percent', minimumFractionDigits: 1 },
    'de-DE'
  )}
/>;
```

You don't normally need `margin` or `funnelWidth`: a composite `labelFormat`
beside the funnel narrows the funnel on its own to leave the label room to wrap
into.

<Callout>
  Label room comes from `funnelWidth`, not `margin`. A label word-wraps against
  the gap between its own segment and the **plot area's** edge — and a margin
  moves that edge inward together with the funnel, so widening `margin.right`
  leaves a long label with *less* room, not more. Narrowing the funnel is what
  frees real space, because the plot area stays put. There is no equivalent
  lever for `labelPosition="left"`: the widest segment always sits flush against
  the plot area's left edge, so a long left-hand label wraps regardless.
</Callout>

`margin` is merged over the defaults per side, so `margin={{ right: 160 }}` keeps
the default top, bottom and left. Reach for it when a label can't wrap at all (one
long word) and you need more room before the SVG edge.

## Legend

`showLegend` renders one entry per visible stage, labelled and colored from
`config`; `legendPos` moves it to the top edge.

```tsx
<FunnelChart
  config={config}
  data={data}
  dataKey="value"
  nameKey="stage"
  labelFormat="value"
  showLegend
  legendPos="top"
/>
```

## Coloring

`colorMode="gradient"` ramps a single hue from the widest stage down to the
narrowest instead of giving each stage its own color — useful when the stages are
one metric dropping off rather than four unrelated categories. The ramp's base is
the first stage's own color — its `stageSettings` override if it has one, otherwise
its `config` color — unless `gradientColor` names another; each stage below it is
mixed further toward the surface, so every segment stays opaque and on-segment
labels keep their contrast.

```tsx
<FunnelChart
  config={config}
  data={data}
  dataKey="value"
  nameKey="stage"
  colorMode="gradient"
  gradientColor="var(--ui-background-brand-primary)"
/>
```

`stageSettings` overrides one stage at a time, keyed by its `nameKey` value:
`color` wins over both `config` and `colorMode`, and `hidden` drops the stage
from the funnel, its labels, the legend, and the conversion percentages.

```tsx
<FunnelChart
  config={config}
  data={data}
  dataKey="value"
  nameKey="stage"
  stageSettings={{
    Trials: { color: 'var(--ui-background-status-strong-info)' },
    Purchases: { hidden: true },
  }}
/>
```

## Segment style and geometry

`stroke` / `strokeWidth` separate the stages with a border, `funnelWidth` narrows
the shape (px or a percentage of the plot area), and `margin` overrides the
reserved insets described above. `showActiveShape` outlines the hovered segment
rather than changing its fill, so it keeps the color that ties it to its legend
entry.

`strokeWidth` on its own is enough: the renderer's own default segment border is a
hardcoded white that the chart container neutralizes, so a bare `strokeWidth` would
otherwise widen an invisible line. Given alone it pairs with
`--ui-border-on-surface-border`.

Use the **`strong`** status tokens (`--ui-background-status-strong-info`, …) for
stage colors, not the plain `--ui-background-status-*` ones — those are the light
tints meant for banners and they wash out as a chart fill.

```tsx
<FunnelChart
  config={config}
  data={data}
  dataKey="value"
  nameKey="stage"
  stroke="var(--ui-border-on-surface-border)"
  strokeWidth={2}
  funnelWidth="65%"
  showActiveShape
/>
```

## Custom tooltip

Replace the tooltip with a configured `ChartTooltipContent` — imported from the
same library, so you never compose recharts yourself. Its `formatter` renders
each row and `labelFormatter` the header, giving you custom formatting, per-series
content, and extra fields:

```tsx
import { FunnelChart, ChartTooltipContent } from '@acronis-platform/ui-react';

<FunnelChart
  config={config}
  data={data}
  dataKey="value"
  nameKey="stage"
  tooltipContent={
    <ChartTooltipContent
      nameKey="stage"
      hideLabel
      formatter={(value, name) => `${name}: ${value.toLocaleString()}`}
    />
  }
/>;
```

## Animation

Charts render statically by default. Opt in to an entrance animation with
`animate`, and tune it with `animationDuration` / `animationBegin` /
`animationEasing`:

```tsx
<FunnelChart
  config={config}
  data={data}
  animate
  animationDuration={800}
  animationEasing="ease-out"
/>
```

`animate` honors `prefers-reduced-motion`: for a visitor who has asked their
system to reduce motion, the series render at their final geometry with no
animation (the same applies when rendering on the server).

## Accessibility

`FunnelChart` sets no `role` and no `aria-*` of its own, and the SVG the funnel is
drawn into has no accessible name. That gap belongs to this component rather than
recharts: recharts takes `title`, `desc` and `role` as first-class chart props and
writes them straight into the plot's `<svg>`, but `FunnelChart` passes none of them
down — it spreads the props you give it onto its own root `<div>` and hands the
recharts chart only the data it computes itself, so the `<title>` / `<desc>` pair
recharts always emits stays empty. recharts' accessibility layer is on by default
and is not switched off here, so the plot is also a tab stop carrying
`role="application"`: a focus stop that announces neither a name nor any data. The
component exposes no way to turn that off.

So put the name on the root, which spreads the props you pass. Choose the role
before copying the snippet: `role="img"` names the chart but also makes its subtree
presentational, and it does not remove the focusable plot inside it — wrapping the
chart in a `<figure>` with a `<figcaption>` is often the better fit here.
`aria-labelledby` works the same way as `aria-label`.

```tsx
<FunnelChart
  role="img"
  aria-label="Conversion funnel: 5,000 visits, 2,600 signups, 1,400 trials, 620 purchases"
  config={config}
  data={data}
  dataKey="value"
  nameKey="stage"
/>
```

Either way, a name is not a text alternative. A funnel is a visual encoding of
numbers, so the numbers themselves have to be reachable as text — a caption, a
summary sentence, or a table beside the chart. The stage labels (`showLabels`, on by
default) and the value labels (`showValueLabels`) are real `<text>` rather than
pixels, but they sit in the SVG with no structural role, and a stage's name and its
value are two separate label lists on opposite sides with nothing tying them
together. `showLegend` and the tooltip are ordinary HTML laid out beside the SVG, so
the legend is the one part of a funnel that is already reliable text.

## Direction (RTL)

Under `dir="rtl"` the chrome around the plot — the legend, the tooltip, and any
readouts you compose alongside them — mirrors on its own, because it is ordinary
flow layout built from logical CSS utilities. The plot area deliberately stays
left-to-right: recharts places every mark in physical SVG coordinates, so mirroring
it would flip the reading order of the data without flipping the geometry that
encodes it. `ChartContainer` holds that in place by pinning `.recharts-surface` to
`direction: ltr`.

For a funnel the pin is what fixes the labels, not just the trapezoids. A funnel's
labels are inside the plot, and recharts anchors a `left`- or `right`-positioned
label with the direction-relative SVG keywords `text-anchor: start` / `end` —
under an inherited `dir="rtl"` those would mirror each label back across the
segment it names, while the segment itself stayed put. With the pin they don't,
which is why `labelPosition` and `valuePosition` name physical sides: `right` is
the right of the funnel in both directions, and the plot-area inset reserved for
a label follows the same side. `labelPosition="inside"` is anchored `middle` and is direction-immune
either way. The pin stops at the surface, so the legend and the tooltip — HTML
outside it — still mirror with the page.
