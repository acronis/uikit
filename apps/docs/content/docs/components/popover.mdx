## Usage

```tsx
import {
  Popover,
  PopoverBody,
  PopoverContent,
  PopoverFooter,
  PopoverPortal,
  PopoverTrigger,
} from '@acronis-platform/ui-react';
```

`Popover` renders a portaled, anchored panel styled by the `--ui-popover-*`
design tokens — container color, border color and width, radius, and min/max
width. Text stays on the bridged `text-foreground` semantic token, which the
design references directly rather than through a Popover-specific token.
Enter/exit animations key off Base UI's `data-[open]` / `data-[closed]` /
`data-[side]` attributes.

It is a **compound** component. `Popover` is the root and owns the open state;
`PopoverTrigger` toggles the panel and acts as its positioning anchor;
`PopoverContent` is the portaled, positioned popup (`side` / `align` /
`sideOffset`). Two optional parts match the Figma node's slots: `PopoverBody`
wraps the main content with the `--ui-popover-body-*` gap and vertical padding,
and `PopoverFooter` is the default end-aligned action row on the shared
`--ui-footer-*` tier.

Positioning, focus management, `Esc` and outside-press dismissal, and the
`role="dialog"` / `aria-haspopup` / `aria-expanded` / `aria-controls` wiring all
come from Base UI's Popover primitive. Unlike `Dialog`, a popover is
**non-modal** by default: focus moves into the panel on open and returns to the
trigger on close, but it is _not_ trapped and background scroll is not locked —
tabbing past the last focusable element continues into the page. Give the panel
an accessible name when its purpose isn't self-evident: render a heading inside
and reference it, or pass `aria-label` / `aria-labelledby` on the content.

## Examples

A panel with a heading and supporting copy, wrapped in `PopoverBody` for the
design's vertical rhythm:

<DemoReact>
  <PopoverDemo />
</DemoReact>

```tsx
<Popover>
  <PopoverTrigger render={<Button variant="secondary">Open popover</Button>} />
  <PopoverContent>
    <PopoverBody>
      <h4 className="font-medium leading-none">Dimensions</h4>
      <p className="text-sm text-muted-foreground">
        Set the dimensions for the layer.
      </p>
    </PopoverBody>
  </PopoverContent>
</Popover>
```

(The preview above adds `defaultOpen` to the root so the panel stays visible.)

With the default action-row footer — the Figma "Popover" recipe, Cancel + Apply:

```tsx
<Popover>
  <PopoverTrigger render={<Button variant="secondary">Filters</Button>} />
  <PopoverContent>
    <PopoverBody>Drop any content into this slot.</PopoverBody>
    <PopoverFooter>
      <Button variant="secondary">Cancel</Button>
      <Button>Apply</Button>
    </PopoverFooter>
  </PopoverContent>
</Popover>
```

Position the panel with `side`, `align`, and `sideOffset`. It defaults to
`side="bottom"` / `align="center"` at a 4px offset, and flips or shifts to stay
in the viewport when space is tight:

```tsx
<PopoverContent side="right" align="start" sideOffset={8}>
  <PopoverBody>
    Anchored to the trigger's right, aligned to its start edge.
  </PopoverBody>
</PopoverContent>
```

Controlled — drive `open` and react to `onOpenChange`. Pass `modal` on the root
to opt into a scroll lock (`true`) or a focus trap without one
(`'trap-focus'`):

```tsx
const [open, setOpen] = useState(false);

<Popover open={open} onOpenChange={setOpen}>
  {/* …trigger + content… */}
</Popover>;
```

When the popover renders inside an isolated container (e.g. a shadow root), pass
a `portalContainer` so the panel inherits that scope's styles. The docs previews
rely on this — `DemoReact` supplies the container through
`PortalContainerProvider`, so the demo above needs no extra plumbing. Set
`portal={false}` only when you supply your own `PopoverPortal` ancestor:

```tsx
<PopoverContent portalContainer={mountNode}>{/* … */}</PopoverContent>
```

## API Reference

### PopoverContent

`Popover` (root) takes the Base UI Popover root props — `open` / `defaultOpen` /
`onOpenChange`, plus `modal` (default `false`). `PopoverTrigger` and
`PopoverPortal` are the matching Base UI parts unchanged. `PopoverBody` and
`PopoverFooter` accept the standard attributes of the `<div>` they render. See
the [Base UI Popover docs](https://base-ui.com/react/components/popover) for the
full prop surface of each part.
