## Usage

```tsx
import {
  FilterSearch,
  FilterSearchActions,
  FilterSearchFilters,
  FilterSearchAppliedFilters,
  useFilterSearchFilters,
} from '@acronis-platform/ui-react';
```

`FilterSearch` is the toolbar that sits above a data table: a horizontal row
arranging a search field, an optional tenant/scope switcher, an optional filter
popover, and trailing action buttons. The root is a pure layout wrapper — a flex
row with a 16px gap and centred children — so you place
[`InputSearch`](/components/input-search), [`Select`](/components/select),
`FilterSearchFilters`, and `FilterSearchActions` as direct children.
`FilterSearchActions` is the trailing area that pushes its content to the end.

There is no `--ui-filter-search-*` token tier: spacing is the Figma
`gap/gap-16` value and every child brings its own tier
([`Search`](/components/input-search), `Select`, `Button`, `Chip`, `Popover`).

`FilterSearchFilters` is the filter popover: a trigger button opening a form with
a Reset filters / Cancel / Apply footer over a **draft** copy of the applied
filters. It snapshots `value` on open, lets field children mutate the draft, and
only commits back through `onValueChange` (plus the optional `onApply`) when
**Apply** is pressed — disabled until the draft actually differs from the applied
value. Reset filters clears the draft (disabled when already empty); **Cancel**,
Escape, and an outside press revert it. Fields taller than the popover scroll
internally.

`FilterSearchAppliedFilters` renders the applied filters as removable chips plus
a top-level **Reset filters** that clears everything immediately, no popover
involved. It is a separate component rendered as a sibling row **below**
`FilterSearch`, and renders nothing when there are no applied filters.

Filter fields are plain `children` inside `FilterSearchFilters` — no render prop.
Each field wires itself to the draft with the `useFilterSearchFilters()` context
hook, which returns the draft `filters` map and a per-key `setFilter` setter:

```tsx
function StatusField() {
  const { filters, setFilter } = useFilterSearchFilters();
  return (
    <InputSelect
      items={STATUS_ITEMS}
      value={(filters.status as string) ?? 'all'}
      onValueChange={(value) =>
        setFilter('status', value === 'all' ? undefined : value)
      }
    >
      {/* … */}
    </InputSelect>
  );
}
```

Setting a key to `undefined` removes it from the draft. Group fields with a
[`Separator`](/components/separator) as a layout convention. Calling
`useFilterSearchFilters()` outside a `FilterSearchFilters` popover throws.

Use it above a data table for search, filtering, and bulk-action controls. For
global search use [`SearchGlobal`](/components/search-global); for a
selection/bulk-action bar use [`Toolbar`](/components/toolbar); when working
inside the `DataTable` composition use its own `DataTableToolbar`.

> **Design-pending.** `FilterSearch` / `FilterSearchActions` map to a real Figma
> node. `FilterSearchFilters` and `FilterSearchAppliedFilters` don't yet — they
> theme entirely from shared semantic tokens plus their composed components'
> tiers, and will be reconciled against the real design once a mockup lands.

## Examples

  <FilterSearchDemo />
</DemoReact>

A full toolbar — tenant switcher, search, filter popover, and the applied-filter
chip row below it:

```tsx
function DeviceFilterFields() {
  return (
    <>
      <TypeField />
      <PricingModeField />
      <Separator />
      <StatusField />
    </>
  );
}

function TableToolbar() {
  const [filters, setFilters] = useState<Record<string, unknown>>({});

  return (
    <div className="flex flex-col gap-3">
      <FilterSearch>
        <Select items={TENANT_ITEMS} defaultValue="acme">
          <SelectTrigger className="w-56">
            <SelectValue placeholder="All customers" />
          </SelectTrigger>
          <SelectContent>{/* … */}</SelectContent>
        </Select>
        <InputSearch
          placeholder="Enter text to filter"
          aria-label="Search"
          className="w-56"
        />
        <FilterSearchFilters
          value={filters}
          onValueChange={setFilters}
          label="Table filters"
        >
          <DeviceFilterFields />
        </FilterSearchFilters>
      </FilterSearch>
      <FilterSearchAppliedFilters
        filters={filters}
        onValueChange={setFilters}
      />
    </div>
  );
}
```

Search only — no tenant switcher or filters:

```tsx
<FilterSearch>
  <InputSearch
    placeholder="Search table"
    aria-label="Search"
    className="w-56"
  />
</FilterSearch>
```

With trailing action buttons in `FilterSearchActions`:

```tsx
<FilterSearch>
  <InputSearch
    placeholder="Search table"
    aria-label="Search"
    className="w-56"
  />
  <FilterSearchFilters value={filters} onValueChange={setFilters} />
  <FilterSearchActions>
    <Button>Export</Button>
  </FilterSearchActions>
</FilterSearch>
```

Chip labels default to `"<key>: <value>"` — pass `getFilterChipLabel` to render
a human-readable field name:

```tsx
<FilterSearchAppliedFilters
  filters={filters}
  onValueChange={setFilters}
  getFilterChipLabel={(key, value) =>
    `${FILTER_LABEL_BY_KEY[key] ?? key}: ${String(value)}`
  }
/>
```

### FilterSearch / FilterSearchActions

Both are layout wrappers with no props of their own — they accept the standard
`<div>` attributes (`FilterSearchProps` and `FilterSearchActionsProps` are
aliases for them).

### useFilterSearchFilters

Returns `{ filters, setFilter }` — the current draft filter map and a
`setFilter(key, value)` setter for wiring filter-field children to the popover
draft. Passing `undefined` as the value removes the key. Throws outside a
`FilterSearchFilters` popover.
