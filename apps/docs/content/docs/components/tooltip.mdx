## Usage

```tsx
import {
  Tooltip,
  TooltipContent,
  TooltipProvider,
  TooltipTrigger,
} from '@acronis-platform/ui-react';
```

`TooltipContent` renders a portaled hint bubble styled by the `--ui-tooltip-*`
design tokens — container color and radius, horizontal/vertical padding, min/max
width, and label color. It's a dark, ~90%-opaque bubble with a light label, and
it renders **no arrow**, matching the Figma design.

It is a **compound** component. `Tooltip` is the root and owns the open state;
`TooltipTrigger` is the hover/focus anchor and is polymorphic via `render`, so it
can wrap any focusable element (typically a `Button` or `ButtonIcon`);
`TooltipContent` is the portaled, positioned popup. `TooltipProvider` is optional
— wrap the app or a region in it to share open/close timing, so once one tooltip
is visible its neighbours open instantly. ui-react defaults its `delay` to
`300` ms.

Hover/focus open behavior, positioning, portalling, and ARIA all come from Base
UI's Tooltip primitive: the popup gets `role="tooltip"` and the trigger
references it via `aria-describedby` while open. Focus **never** moves into the
popup — it opens on focus, closes on blur or `Esc`, and holds no interactive
content. Because of that, a tooltip is supplementary only: it's unavailable to
touch users and vanishes on blur, so never put critical information or actions in
one, and never rely on it as an icon-only control's sole accessible name — give
the control its own `aria-label` as well.

## Examples

A hint on a button. `TooltipTrigger` composes with the `Button` through `render`,
keeping the button's own styling and props:

<DemoReact>
  <TooltipDemo />
</DemoReact>

```tsx
<Tooltip>
  <TooltipTrigger render={<Button variant="secondary">Hover me</Button>} />
  <TooltipContent>Helpful hint</TooltipContent>
</Tooltip>
```

(The preview above adds `defaultOpen` to the root so the bubble stays visible.)

Placement — `side` defaults to `top` at a 6px `sideOffset`, with `align`
defaulting to `center`. The bubble flips to the opposite side when there isn't
room:

```tsx
<Tooltip>
  <TooltipTrigger render={<Button variant="secondary">Top</Button>} />
  <TooltipContent side="top">On top</TooltipContent>
</Tooltip>
<Tooltip>
  <TooltipTrigger render={<Button variant="secondary">Right</Button>} />
  <TooltipContent side="right">On right</TooltipContent>
</Tooltip>
<Tooltip>
  <TooltipTrigger render={<Button variant="secondary">Bottom</Button>} />
  <TooltipContent side="bottom">On bottom</TooltipContent>
</Tooltip>
<Tooltip>
  <TooltipTrigger render={<Button variant="secondary">Left</Button>} />
  <TooltipContent side="left" align="start" sideOffset={12}>
    On left
  </TooltipContent>
</Tooltip>
```

Share timing across many tooltips with a provider — the typical use for an icon
toolbar, where re-waiting the full delay on every button would feel sluggish:

```tsx
import { PencilIcon } from '@acronis-platform/icons-react/stroke-mono';

<TooltipProvider delay={500}>
  <Tooltip>
    <TooltipTrigger
      render={
        <ButtonIcon aria-label="Edit">
          <PencilIcon />
        </ButtonIcon>
      }
    />
    <TooltipContent>Edit</TooltipContent>
  </Tooltip>
  {/* …more tooltips… */}
</TooltipProvider>;
```

`anchor` overrides what the bubble is positioned against, which defaults to the
trigger element. Reach for it when the hover/focus target is narrower than the
element the tooltip should visually align to — e.g. a truncating label inside a
full-width row, where the bubble should sit against the row's edge, not the
label's:

```tsx
const rowRef = useRef<HTMLDivElement>(null);

<div ref={rowRef}>
  <Tooltip>
    <TooltipTrigger render={<span className="truncate">{longLabel}</span>} />
    <TooltipContent anchor={rowRef}>{longLabel}</TooltipContent>
  </Tooltip>
</div>;
```

Controlled — drive `open` and react to `onOpenChange`; `disabled` on the root
stops the tooltip from ever opening:

```tsx
const [open, setOpen] = useState(false);

<Tooltip open={open} onOpenChange={setOpen}>
  <TooltipTrigger render={<Button variant="secondary">Controlled</Button>} />
  <TooltipContent>Controlled tooltip</TooltipContent>
</Tooltip>;
```

When the tooltip renders inside an isolated container (e.g. a shadow root), pass
a `portalContainer` so the bubble inherits that scope's styles. The docs previews
rely on this — `DemoReact` supplies the container through
`PortalContainerProvider`, so the demo above needs no extra plumbing:

```tsx
<TooltipContent portalContainer={mountNode}>Helpful hint</TooltipContent>
```
