## Usage

```tsx
import { Meter } from '@acronis-platform/ui-react';
```

`Meter` shows a scalar value within a known range — a **fractional value / share**
— as a labelled bar: label + `value · %` over a proportional track, with a hover
tooltip. It's built on Base UI's `Meter` (`role="meter"`, like the HTML
`<meter>` element) — a share, not task progress over time. Stack several — sharing one `max`
(the total), sorted by value — to build a **ranked breakdown** (a "bar list").

> **Design-pending v1.** No chart token tier yet, so the fill `color` is
> **caller-supplied** per row (a dedicated `--ui-chart-*` data-viz palette is
> pending an upstream design pass). The tooltip uses the chart-tooltip look
> (light card). Code Connect deferred.

## Examples

A ranked breakdown built from stacked meters:

<DemoReact>
  <MeterDemo />
</DemoReact>

A single meter:

```tsx
<Meter
  label="Critical"
  value={6}
  max={29}
  color="var(--ui-background-status-strong-danger)"
/>
```

Stack several sharing one `max` (the total), sorted by value:

```tsx
const rows = [
  { label: 'High', value: 9, color: 'var(--ui-background-status-strong-warning)' },
  { label: 'Medium', value: 8, color: 'var(--ui-background-status-strong-info)' },
  { label: 'Critical', value: 6, color: 'var(--ui-background-status-strong-danger)' },
];
const total = rows.reduce((sum, r) => sum + r.value, 0);

<div className="flex flex-col gap-4">
  {rows
    .sort((a, b) => b.value - a.value)
    .map((r) => (
      <Meter key={r.label} label={r.label} value={r.value} max={total} color={r.color} />
    ))}
</div>;
```

Hide the hover tooltip with `showTooltip={false}`, format the value with
`valueFormatter`, or replace the tooltip's contents with `tooltip` — a custom
node rendered inside the same chart-style card.

## Accessibility

`Meter` is Base UI's `Meter`, so the root is a `role="meter"` — a scalar value
within a known range, which is exactly why it isn't a `progressbar` — carrying
`aria-valuenow`, `aria-valuemin` (0), `aria-valuemax`, and an accessible name
wired from the `label` prop through `Meter.Label` and `aria-labelledby`.
`aria-valuemax` is set back to the real `max` explicitly: a non-positive `max`
is floored at 1 internally so the fill math can't divide by zero, and the
numeric triad should still report what you passed.

`aria-valuetext` is what a screen reader actually reads for the value —
`"<value> of <max> (<percent>%)"`. Both numbers go through `valueFormatter`, so
a formatter that appends a unit or a currency symbol changes the announcement as
well as the visible row. The connective wording between them is the component's
own English and is not reachable through that prop.

With the tooltip on (the default) the root takes `tabIndex={0}` so the hover
card is reachable by keyboard; with `showTooltip={false}` it is not focusable,
because there is nothing to reveal. Either way the value and its share are plain
text in the row, so a stack of meters stays readable without color — which is
why every fill is paired with its label.

## Direction (RTL)

Plain DOM with no physical directional utilities, so a meter mirrors under
`dir="rtl"`: the label moves to the inline start (the right) and the
`value · %` readout to the inline end. Base UI positions the fill with
`inset-inline-start`, so the bar grows from the same edge the label starts at.
