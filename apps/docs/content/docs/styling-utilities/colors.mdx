[`@acronis-platform/tokens-pd`](/packages/tokens-pd) generates one utility
class per existing `--ui-text-*`/`--ui-background-*`/`--ui-border-*` custom
property, so non-Tailwind
[`@acronis-platform/ui-react`](/getting-started) consumers can reach every
semantic color role by class instead of hand-writing `var(--ui-...)`:

```tsx
<p className="ui-text-on-surface-destructive">Something went wrong</p>
<div className="ui-bg-surface-primary ui-border-on-surface-border" />
```

<Callout type="info">
  **Full path, no truncation.** `--ui-text-on-surface-link-idle` becomes
  `.ui-text-on-surface-link-idle`, not a hand-picked short alias — the class
  name mirrors the token name verbatim, same convention as every other
  utility in this grammar (`ui-top-16`, `ui-border-t-4`, …). `background`
  shortens to `bg` in the class **prefix** only (matching Tailwind's own
  convention) — the token's own path/suffix is never touched.
</Callout>

| Prefix | Property | Token root |
| --- | --- | --- |
| `ui-text-*` | `color` | `--ui-text-*` |
| `ui-bg-*` | `background-color` | `--ui-background-*` |
| `ui-border-*` | `border-color` | `--ui-border-*` |

This is a **mechanical, generated wrapper** — every role that exists in the
semantic tier gets a class, driven by the resolved token stream at build
time, not a hardcoded list. A new color token added upstream gets a class
for free on the next build.

<Callout type="warn">
  This is not an exhaustive list here — see [Token
  reference](/token-reference) for every `--ui-*` custom property. This page
  only documents the **class** layer on top of them.
</Callout>

## State variants

Every semantic color class above also has `hover`/`disabled`/`focus-visible`/
`last` forms, generated by a generic multiplier — a future color class
automatically gets these for free, no build change needed:

```tsx
<button className="ui-text-on-surface-primary ui-hover:text-on-brand-primary">
  Hover me
</button>
```

| Variant | Pseudo-class |
| --- | --- |
| `ui-hover:` | `:hover` |
| `ui-disabled:` | `:disabled` |
| `ui-focus-visible:` | `:focus-visible` |
| `ui-last:` | `:last-child` |

<Callout type="info">
  Naming mirrors Tailwind's own `variant:utility` syntax exactly — the colon
  is escaped in the generated CSS selector
  (`.ui-hover\:text-on-surface-primary:hover`), which matches an unescaped
  `className="ui-hover:text-on-surface-primary"` the same way Tailwind's own
  compiled `hover:` classes do.
</Callout>

<Callout type="warn">
  There are also **static** `-hover`/`-active`/`-pressed` token roles for
  some colors (e.g. `ui-bg-brand-primary-hover`) — those are a different,
  always-on color choice for a role that already varies by state in the
  design system, not a `:hover` pseudo-class. Use the `ui-hover:*` variant
  when you want the class to apply **only** on hover; use the `-hover` role
  directly when you want that value unconditionally.
</Callout>

<Callout type="warn">
  All of the above is generated from `@acronis-platform/design-tokens` by the
  `tools/style-dictionary` pipeline and committed to git. Never hand-edit
  `css/default.css` directly.
</Callout>
