# `.ui-*` utility grammar — extension spec

Tracking ticket: [PLTFRM-94106](https://pmc.acronis.work/browse/PLTFRM-94106)
("Extend the `.ui-* `utility grammar: sizing, semantic colors, state variants —
for consumers without a Tailwind build").

## Background

`@acronis-platform/tokens-pd` ships a small, framework-agnostic `.ui-*` class
grammar for consumers who can't extend the kit's Tailwind preset (e.g. MFEs
that adopt kit styles into a shadow root via `adoptedStyleSheets`). Today it
covers exactly two families, both generated by
`tools/style-dictionary/src/hooks/formats/`:

- Spacing — `.ui-p-*`/`.ui-m-*`/`.ui-gap-*` (`gap-utility-classes.ts`)
- Typography — `.ui-typography-*` (`typography-css-class.ts`)

Everything else (color, sizing, shadow, border, state variants) has no `.ui-*`
equivalent, even though the underlying `--ui-*` custom properties and Tailwind
theme keys already exist. A mechanical audit of the policy-management MFE
migration and a survey of 22 consuming MFEs both converge on the same gaps —
see the ticket for the full evidence and prioritization discussion.

This document specs the next batch: the items with no dependencies (no new
generator capability, no upstream `design-tokens` change) that can ship
immediately, mirroring the existing spacing-emitter pattern.

## Scope of this batch ("Now")

1. `ui-w-*` / `ui-h-*` sizing, mirroring the spacing scale
2. Layout & text-flow primitives — flex, grid, non-flex alignment, text
   wrapping/overflow. Explicitly **not** typography (no font-size/weight/
   family/line-height — those stay in `.ui-typography-*`).

Everything else from the ticket (semantic color wrappers, `ui-shadow-*`,
fixed max-width/fraction scales, border-radius, the state-variant compiler)
is out of scope here — tracked separately.

---

## 1. `ui-w-*` / `ui-h-*` sizing

Mirror the existing spacing scale 1:1 — same 17 steps that already back
`ui-p-*`/`ui-m-*`/`ui-gap-*`, same `--ui-gap-<n>` custom property, just applied
to `width`/`height` instead of box-model properties.

**Scale steps:** `0, 2, 4, 6, 8, 12, 16, 20, 24, 32, 40, 48, 56, 64, 72, 88, 96`

| Prefix  | Property     |
| ------- | ------------ |
| `w`     | `width`      |
| `h`     | `height`     |
| `min-w` | `min-width`  |
| `min-h` | `min-height` |
| `max-w` | `max-width`  |
| `max-h` | `max-height` |

Example output:

```css
.ui-w-40 {
  width: var(--ui-gap-40);
}
.ui-h-40 {
  height: var(--ui-gap-40);
}
.ui-min-w-64 {
  min-width: var(--ui-gap-64);
}
.ui-max-h-96 {
  max-height: var(--ui-gap-96);
}
```

Plus one static class, mirroring `.ui-mx-auto`:

```css
.ui-max-w-full {
  max-width: 100%;
}
```

**Implementation:** extend `resolveGapTokens`'s consumer in `tokens.ts` to also
call a new `sizingUtilityClasses(varName, sizeKey)` (sibling to
`gapUtilityClasses` in a new `sizing-utility-classes.ts`, same shape: a
`Record<string, string>` of prefix→CSS property, looped over the same gap
token stream) instead of overloading the existing padding/margin/gap map.
Keep it a separate file/function — sizing and spacing are different concerns
that happen to share a scale, and the existing file's naming
(`gap-utility-classes.ts`) is spacing-specific.

**Not in this batch:** the Tailwind-named fixed scale (`w-1/2`, `w-1/3`,
`max-w-xs`…`max-w-7xl`). Those are a _different_, finite, non-token-driven set
— tracked as a follow-up ("Next" tier in the ticket).

## 2. Layout & text-flow primitives

Not token-driven — these are finite, fixed sets, so "complete" means copying
Tailwind's own utility groups wholesale (same principle as the ticket's
"misc/layout primitives" note), not a hand-picked subset. All static classes,
same pattern as `.ui-mx-auto`. Deliberately **excludes anything typographic**
(font-size, font-weight, font-family, line-height, letter-spacing) — those are
owned by `.ui-typography-*` and stay there; mixing atomic type overrides into
this batch would undermine that composite system.

### Flex

```css
.ui-flex {
  display: flex;
}
.ui-inline-flex {
  display: inline-flex;
}
.ui-flex-row {
  flex-direction: row;
}
.ui-flex-row-reverse {
  flex-direction: row-reverse;
}
.ui-flex-col {
  flex-direction: column;
}
.ui-flex-col-reverse {
  flex-direction: column-reverse;
}
.ui-flex-wrap {
  flex-wrap: wrap;
}
.ui-flex-nowrap {
  flex-wrap: nowrap;
}
.ui-flex-1 {
  flex: 1 1 0%;
}
.ui-flex-auto {
  flex: 1 1 auto;
}
.ui-flex-initial {
  flex: 0 1 auto;
}
.ui-flex-none {
  flex: none;
}
.ui-grow {
  flex-grow: 1;
}
.ui-grow-0 {
  flex-grow: 0;
}
.ui-shrink {
  flex-shrink: 1;
}
.ui-shrink-0 {
  flex-shrink: 0;
}
```

### Grid

```css
.ui-grid {
  display: grid;
}
.ui-inline-grid {
  display: inline-grid;
}
.ui-grid-cols-1 … .ui-grid-cols-12 {
  grid-template-columns: repeat(<n>, minmax(0, 1fr));
}
.ui-grid-rows-1 … .ui-grid-rows-6 {
  grid-template-rows: repeat(<n>, minmax(0, 1fr));
}
.ui-col-span-1 … .ui-col-span-12 {
  grid-column: span <n> / span <n>;
}
.ui-row-span-1 … .ui-row-span-6 {
  grid-row: span <n> / span <n>;
}
```

### Alignment (flex + grid containers/items)

```css
.ui-items-start / -end / -center / -baseline / -stretch {
  align-items: …;
}
.ui-justify-start / -end / -center / -between / -around / -evenly {
  justify-content: …;
}
.ui-content-start / -end / -center / -between / -around / -evenly / -stretch {
  align-content: …;
}
.ui-self-auto / -start / -end / -center / -stretch / -baseline {
  align-self: …;
}
.ui-justify-self-auto / -start / -end / -center / -stretch {
  justify-self: …;
}
```

### Alignment outside flex/grid

```css
.ui-text-left / -center / -right / -justify / -start / -end {
  text-align: …;
}
.ui-align-baseline / -top / -middle / -bottom / -text-top / -text-bottom {
  vertical-align: …;
}
.ui-float-left / -right / -none {
  float: …;
}
.ui-clear-left / -right / -both / -none {
  clear: …;
}
```

### Text wrapping / overflow (flow control, not type styling)

```css
.ui-whitespace-normal / -nowrap / -pre / -pre-line / -pre-wrap / -break-spaces   { white-space: …; }
.ui-break-normal / -words / -all / -keep   { overflow-wrap / word-break: …; }
.ui-truncate   { overflow: hidden; text-overflow: ellipsis; white-space: nowrap; }
.ui-text-ellipsis / .ui-text-clip   { text-overflow: ellipsis / clip; }
.ui-line-clamp-1 … .ui-line-clamp-6, .ui-line-clamp-none   { -webkit-line-clamp: <n>; overflow: hidden; display: -webkit-box; -webkit-box-orient: vertical; }
.ui-hyphens-none / -manual / -auto   { hyphens: …; }
```

### Display (needed to make the flex/grid switches useful)

```css
.ui-block / .ui-inline-block / .ui-inline / .ui-hidden / .ui-contents
```

**Implementation:** a new hook, e.g. `hooks/formats/layout-utility-classes.ts`,
producing static `Map<selector, declaration>` entries exactly like
`STATIC_GAP_CLASSES` — none of this is token-derived, so it doesn't touch
`tokens.ts`'s resolve pass at all. Grid `col-span`/`row-span`/`grid-cols`/
`grid-rows` counts should match Tailwind's own default scale (12 cols, 6 rows)
so consumers don't hit a silent ceiling partway through porting markup.

**Not in this batch:** anything with a numeric gap between grid tracks beyond
`ui-gap-*` (already covered), and any `hover:`/responsive-variant form of these
classes — that's the state-variant/breakpoint-variant compiler work, tracked
separately.

## Open questions before implementation

- Docs IA: these new classes should land under
  `apps/docs/content/docs/styling-utilities/`, alongside spacing and
  breakpoints — needs new `sizing.mdx` and `layout.mdx` pages plus a
  `meta.json` update.
- Confirm the exact grid column/row ceiling (12/6, matching Tailwind's
  default) is enough, or whether any consumer needs more.
- Confirm `.ui-hidden` doesn't collide with any existing consumer convention
  (some teams use a local `.hidden` already) before shipping it under the
  `ui-` prefix.
