## Caveats from the version research

- **nanoid** (#89, #90): the only version that both fixes the issue and clears the 21-day bar is a breaking major (`6.0.1`, 23d old). `3.3.18` fixes it but is only 19 days old (2 days short). Given nanoid's massive install base and trivial fix surface, `3.3.18` is still the pragmatic recommendation — re-check in ~2 days if the 21-day rule must be strictly honored, or accept the major bump to `6.0.1`.
- **fast-json-patch** (#15) and **js-yaml** `packages/ui-react` alert (#93): both are marked "✅ bumped" in the prior version of this doc, but the installed versions (`3.1.0` and `4.3.0` respectively) do **not** actually meet the advisories' own `first_patched_version` (`3.1.1` and `4.3.1`). Worth re-verifying and re-bumping despite the earlier checkmark.
- **js-yaml** `3.14.2` transitive resolution (via `@changesets/cli` → `@manypkg/get-packages` → `read-yaml-file`) can only be fixed with a pnpm override (`>=3.15.1`), not a direct dependency bump.
- **vite**: the `6.4.3` catalog-pinned resolution is unaffected and intentionally held per the `pnpm-workspace.yaml` comment (rolldown/CJS interop issue) — do not touch it. Only the `8.0.14` transitive resolution pulled in via `fumadocs-mdx` in `apps/docs` is in the vulnerable range and needs the bump to `8.2.0`.
- **axios, fast-uri, immutable, joi, react-router, sharp** are all transitive-only in this repo (no direct `package.json` entry) — bumping them requires either waiting on the parent dependency's own bump, or adding a pnpm override.
- **form-data, postcss, uuid, ajv, undici (#28/#32)** have no remaining open alert — the currently installed version already satisfies the fix; the safest-version column reflects the best currently available release rather than a required bump.
